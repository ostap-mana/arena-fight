# Підключення гри до панелі аналітики

Привіт! Це інструкція, як підключити твою веб-гру (плейбл) до нашої спільної панелі аналітики. Разом із цим файлом ти отримав `telemetry.js`.

Після підключення в панелі буде видно:
- скільки людей грало і за якими посиланнями;
- спроби, перемоги й поразки, тривалість гри;
- кнопки «Ще раз» і CTA;
- fps, ривки, час завантаження;
- порівняння варіантів гри (`?v=`).

Займе 15–30 хвилин. Відтворення спроб (повтор гри) не потрібне.

> **Лише тестова збірка.** У збірку для рекламних мереж SDK не додається: мережі вимагають 0 зовнішніх запитів. Зроби окрему тест-збірку (прапорець збирача).

---

## Крок 1. Заповни й поверни цей блок

Скопіюй, заповни й надішли назад тому, хто дав тобі файл. Без цього сервер не прийматиме дані з твоєї гри.

```
ПРОЄКТ:        tower-run                       ← id латиницею: a-z, 0-9, дефіс, до 32 символів
АДРЕСА ГРИ:    https://tower-run.vercel.app    ← звідки відкривається тест-збірка, без / у кінці
ПРЕВ'Ю-АДРЕСИ: https://tower-run-*.vercel.app  ← якщо є (Vercel preview), інакше «нема»
НАЗВА ГРИ:     Tower Run                       ← як показувати людям
ВАРІАНТИ:      A, B                            ← які ?v= плануєш, або «нема»
КОНТАКТ:       ім'я / телеграм                 ← кому писати, якщо щось не так
```

## Крок 2. Підключи SDK

Поклади `telemetry.js` у проєкт і ініціалізуй **якомога раніше**, до завантаження ассетів. Тоді панель побачить навіть тих, хто пішов під час завантаження.

```js
import { initTelemetry } from './telemetry.js';

const tm = initTelemetry({
  endpoint: 'https://ostap-kreminets.vercel.app/api/ingest',
  project: 'tower-run',          // id з кроку 1
  build: '<git short sha>',      // яка збірка (необов'язково, але дуже корисно)
});
```

Варіант гри SDK сам бере з `?v=` в адресі, а мітку джерела — з `?src=`. Тож посилання для гравців такі:
`https://<гра>/?v=A&src=telegram`. Без `src` гравці будуть у групі «anon».

## Крок 3. Виклики в потрібні моменти

| коли | виклик |
|---|---|
| гра завантажилась, перший кадр | `tm.gameReady()` |
| перший дотик/клік гравця | `tm.firstInput()` |
| почалась спроба (рівень/забіг) | `tm.runStart()` |
| спроба закінчилась | `tm.runEnd({ result: 'win' })` або `'lose'` |
| натиснули «Ще раз» | `tm.retryClicked()`, далі `tm.runStart()` |
| натиснули CTA (стор) | `tm.ctaClicked()` — **до** переходу в стор |

Необов'язково: `runEnd` приймає `stats` — до 24 чисел на твій вибір, наприклад:

```js
tm.runEnd({ result: 'lose', stats: { score: 1200, level: 3, coins: 45 } });
```

Закриття вкладки посеред спроби, сховану сторінку, офлайн і повторну відправку SDK обробляє сам.

## Крок 4 (бажано, 10 хвилин). Продуктивність

- Фази завантаження:
  - `performance.mark('boot.<фаза>:start')` … `performance.measure('boot.<фаза>', 'boot.<фаза>:start')`;
  - на першому кадрі — `performance.mark('boot.firstFrame')`.
- three.js:
  - `tm.setRendererInfo(() => renderer.info)`;
  - `tm.setGl(renderer.getContext())`.

fps, ривки, пам'ять і тип пристрою SDK рахує сам.

## Крок 5. Перевір

1. Дочекайся відповіді, що твою адресу додано (крок 1).
2. Відкрий `https://<гра>/?v=test&src=dev` і зіграй одну спробу.
3. DevTools → Network: запит на `/api/ingest` має повертати **200**.
   - **403** — адресу гри ще не додали (або вона відрізняється від тієї, що в кроці 1).
   - **400** — неправильний `project` (лише `a-z 0-9 -`).
4. Напиши, що зіграв. Ми перевіримо, що сесія `dev` з'явилась у панелі.

Питання — пиши на контакт, від якого отримав файл.
